# Security

## Security Posture

This framework assumes that security is part of delivery, not an afterthought. Every feature and release must be evaluated for data exposure, access control, secrets handling, and dependency risk.

## Required Review Areas

- Authentication and authorization
- Secrets management
- Input validation and sanitization
- API exposure and rate limiting
- Least-privilege configuration
- Secure defaults and safe error handling

## Release Gate

No release is approved without explicit security evidence and documented corrective action for any accepted risk.
