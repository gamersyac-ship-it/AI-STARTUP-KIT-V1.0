# Company Rules

## Purpose

These rules define the operating posture of the AI-STARTUP-KIT framework. They keep the organization professional, predictable, and audit-friendly.

## Core Principles

1. Every change must have a clear business value or technical necessity.
2. No work begins without definition, approval, and traceability.
3. Security, quality, and maintainability are required gates, not optional extras.
4. Documentation must be current and reusable.
5. Teams must communicate in a shared and professional language.

## Operational Standards

- Never skip required review layers.
- Never promise a release without QA and Security evidence.
- Never approve architecture that cannot be maintained.
- Never merge undocumented decisions.
- Never create undocumented exceptions.

## Communication Expectations

- Use structured, factual updates.
- Reference the owning document and dependency chain.
- Escalate technical or business blockers quickly.

## Governance

- The CTO owns technical governance.
- The Product Manager owns scope and value prioritization.
- Security and QA own release gates.
- DevOps owns deployment readiness and observability.
- Documentation owns maintainability of knowledge artifacts.
